# v5 正式导出与隔离启用验证（2026-11-03）

证据位于工作区 `v5/c`、`v5/m` 与 `v5/review`。运行使用 `v5/p/skills` 下可搬迁副本，与候选源码核对字节；任务编排脚本另存，运行依赖均显式绑定。未安装全局技能，也未修改全局 COMSOL 偏好。

## 本轮实际完成

- 新建的正弦初温导热模型：1 次完整 0–1 s 求解、1 次独立保存解读回、1 次正式 `run_bundle.py export`。11 个保存时刻，每时刻45点；温度最大解析误差0.000253621 K。
- 新建的温度反馈电热模型：1 次粗网格稳态求解、1 次独立读回、1 次正式 export，覆盖全部9个目标。建模侧显式设置的 T_ref=300 K 稳态初始化保留；计算侧无物理或初始值修改。
- 两次 export 都只运行导出阶段，源 MPH 哈希不变；实际解、数据集、坐标、单位、位置及原始数值均独立核对。与新保存解读回的数据逐量比较差为0；混合 DOF/网格数据的一致性比较不赋予统一物理单位，也不是收敛证明。
- 1 次真实无解导出负例，在读取既有解时被拒绝，没有求解回退。它是明确审查的直接 Java 负例，不是伪造就绪的公共导出请求。

共2次真实求解、2次独立读回、2次正式导出。另有2次编译和1次真实负例，不能合计成求解次数。独立验收见 `v5/review/transient-export-independent.json`、`nonlinear-export-independent.json`，检查继承另有两个 handoff 独立记录。

## 修复与行为证据

瞬态 Java 原已包含只读 export 分支，但 Python 正式适配器没有接通。本轮补齐 `operation=export`、existing 目标/逻辑记录/实际解身份校验、单导出阶段和既有解观察记录；新增实际数据集解绑定、solnum/time 与 T/K/m 元数据。仅 Java 接受 mode 不再被当作正式入口能力。

瞬态共14项离线测试，包括科学定义拒绝、仅导出分派，以及错误源、解标识、时间、planned目标和缺解记录的前置拒绝。此次分支重排还核验匹配 checkpoint 的 resume 仍进入 solve 阶段，源哈希或起时刻错误在原生阶段前拒绝。**本轮未重新执行半程或接续求解**；v4真实保存场接续保留其原始源码/模型绑定。本轮新增共享读回元数据经新的 full/export 实测，原接续特殊逻辑由差异审查和离线回归补证，不能冒称新 class 又完成了真实接续。

资源保护脚本对 Windows 环境变量按不区分大小写清理继承的 PSModulePath；此前普通字典删除漏掉 PSMODULEPATH，导致 Windows PowerShell 5.1 误用 PowerShell 7 模块。修复仅作用于本次子进程环境，让目标 PowerShell 初始化自己的原生模块路径；不是全局环境修改，也不是新增资源限制。建模正式入口的 PowerShell 5.1 默认配置路径初始化问题也已修复，具体建模证据另存。案例资源和误差界限仍仅属本轮。

## 限制与保留

导出结论限定于这两个明确目标的小模型；任意接口、复杂时间选择、任意网格、频域/模态、崩溃恢复和 BDF 历史恢复仍需针对性验证。现有两级网格证据也不等于一般收敛阶。

模型、编译产物和私有缓存由根执行者在独立验收后清理，保留源码、原始日志、数值 JSON 和哈希/清理回执。清理后的历史载解文件不能再声称可实时核验；本轮验收不授予以后计算权限。
