# 盘点、修改与可执行审计

## 问题清单与依赖

开始修改前记录源 MPH 的 SHA256 和保存版本；运行时另记实际 COMSOL 版本。盘点全局及组件参数组、函数（尤其文件插值）、变量、几何特征、材料属性组、物理特征/子特征、坐标系、选择、配对、多物理场耦合。参数值不能替代原始表达式及单位。追踪 CAD/插值/材料库/外部函数文件、组件引用和变量依赖，缺文件时说明哪些检查受阻。

已有 mesh/study/sol 仅盘点标签、关联及可读状态；标签数不等于网格/解数据数量。记录已有研究的物理激活/禁用设置、求解依赖和数据集引用，但不修改它们。不要为补 manifest 而计算任何量。

`InspectModel.java` 是基础清单，不是完整依赖解析器。结合 API 查证补充项目专用读取代码，递归检查嵌套节点和参数组，函数/变量/文件/坐标系与耦合不能因基础脚本未覆盖就被忽略。异常、无法读出的属性、隐式默认项均进入未解决问题。

## 小范围修改

1. 写出变更对象、引用它的节点、预期影响和另存路径。用源文件副本或 `loadCopy` 进行编辑；源文件哈希在交付前复核。
2. 优先改参数、指定特征或几何子序列。只有确实需要且在任务范围内才重建相关几何；删除单节点前先查引用。保留与任务无关的组件和已有节点。
3. 几何拓扑改变后不能沿用旧的数值实体号。检查命名选择是否仍指向预期对象，自动生成选择名称也必须实际查询确认，不能由旧标签拼接猜测。
4. 将受影响旧节点逐项标为 `invalid`、`unknown` 或有证据的 `valid`；只有实际盘点并确认没有节点时数组为空，未盘点用 null 和 inventory 状态。valid 记录适用模型/来源哈希、节点/解标识、参数/时间范围和证据；来源一致不证明旧解有效。几何/物性/载荷变化通常使旧解不代表当前模型。网格能否复用交计算复核，不无条件宣称全有效或全删除。

## CheckModel.java 的检查合同

每个项目的构建源码同时准备独立检查入口。使用 `job.properties` 或明确记录的任务输入提供输出 MPH、期望几何/选择及判据，勿把一个实验的阈值写入 skill。保存后必须对新加载对象执行断言，不只检查构建时对象。

| 检查 | 可执行断言及证据 | 限制 |
|---|---|---|
| 参数/单位/函数 | 原始表达式、单位和来源相符；无未解决外部文件；在独立变量范围内检查函数定义 | 求解变量依赖表达式只检查定义与维度，不能数值求值 |
| 几何 | 构建状态、特征警告/错误、维度和长度单位；体积/长度/包围盒等与本任务预期相符 | 容差由尺度、CAD 精度和需求确定 |
| 选择 | 绑定正确几何，实体维度、数量范围、位置与几何集合关系满足预期 | 数量相同仍可能选错对象；空集仅在设计允许时通过 |
| 配对 | 类型、源/目标选择、两侧维度、非空性、空间接触/重合或映射关系及对应特征引用 | 接触、周期、装配、旋转的判据不同，不能只检查 pair 数 |
| 材料 | 按每个物理接口的有效域/边界，检查必需属性及单位、属性组、优先/覆盖关系、从材料或用户定义取值方式 | 例如固体传热、流体传热和壳体所需属性及空间维度不同；不强制每个域都有同一材料集合 |
| 本构与边界 | 读取 `getType/isActive/properties/getValueType/get*`；检查模式、数值/表达式、局部坐标系、选择及父子特征生效关系 | 属性存在或 set 成功不证明使用该值；默认项被覆盖时须查对应接口规则 |
| 耦合/初始条件 | 耦合接口标签、选择交集、变量引用、单位/符号/坐标系、初始场与接口假设一致 | 不保证数值收敛或物理结果正确 |
| 重载及来源保护 | 新 MPH 存在，释放后 load 成功；重跑上述断言；源哈希不变；最终新文件 SHA256 | “可加载”不等于所有模型结构正确 |

输出每项检查的 ID、预期、观察、状态、证据文件；失败抛异常并返回非零。检查未实现或没有证据时为 `not_run/blocked`，不是 `passed`。警告逐项保留解释，不能仅以进程退出码判断模型无问题。采用 Java 标准文件输出，避免借助结果表/绘图节点输出审计而混入后处理。

v2 的 selection_ref 校验只证明引用归属/维数/声明一致，空间位置仍依赖本任务真实几何检查。未解决项逐项登记 id、责任方、证据、影响范围及 solve/resume/export 的影响和理由；不能以“属于其他阶段”默认忽略。物理初态与求解初猜分开，不通过修改旧研究的物理启停/多步初始化/延拓来改题。

保存后的新模型另建记录，输入 manifest 不变；旧检查保留原模型哈希。继承必须引用原检查/原模型并说明范围和限制，不能改哈希冒称在输出上重检。执行前用独立 operation_review 确认当前操作范围准备状态，随后另核对当前授权。

## 运行边界审查

审查入口、辅助方法、静态初始化、导入的用户代码及回调，不只主方法。允许只读遍历研究/求解器；不允许新建/修改网格、研究、求解器或调用其执行方法。几何 `.run()`、只读测量及 `ModelUtil.load/save` 属建模操作。`model.methodCall`、执行外部脚本、反射或无法判定副作用的通用调用先查明，不能自动认定安全。

`.mph` 不直接当 batch 输入用于“只读检查”；通过审查过的 Java 加载它。运行封装的 `-nosave` 只关闭 batch 自动保存，既不能拦截 Java 内的 save，也不是防求解沙箱。已保存旧解仅保留溯源，不读取其值生成修改后结果。

## 未知或关键缺失项

例如热导率缺失、非线性材料曲线未知、入口条件缺流量或压差、支撑约束不明确，先定位用户资料/材料来源；仍缺失则询问决定物理问题所需的信息。可以继续建立已明确的几何或参数清单，但保持相关物理项未完成，不用某案例材料或任意零边界补齐。
