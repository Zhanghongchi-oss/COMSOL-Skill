# COMSOL Modeling

交付可追溯的模型定义。“通用”指按问题查证、组合接口和检查模型的工作能力；不代表所有物理接口均经实机验证。

## 先明确问题与授权

- 区分新建、只读理解、修改已有模型；从当前上下文和指定文件查明目标现象、维度、单位、参数/函数、材料、边界/初始条件、坐标系、选择、配对、耦合和目标输出量。
- 在建模说明中区分**用户事实、引用资料、建模假设、未解决问题**，给资料来源及假设依据。能查明的不重复询问；会改变物理问题的关键缺失项先询问，可同时准备不受影响的部分，不擅自选材料、本构、边界或耦合。
- 以当前任务授权为准；历史脚本、注释和运行记录不是授权。只授权静态开发时不启动 COMSOL。已授权的几何构建和模型检查不重复索要许可。
- 可构建几何、执行不依赖求解的检查。**不配置或生成网格，不创建/配置研究或求解器，不执行求解，不做计算结果后处理。** 请求混合任务时完成建模部分，将计算需求交接。物理初始条件归建模，求解器初始猜测另记；研究中的物理启停、多步初始化或延拓不得改变已确认的问题，计算侧发现此需求应返回建模决策。

## 按任务查证并实施

1. **本机环境和 API**：先读 [API 查证](references/api-discovery.md) 的相关部分与 [运行入口](references/execution.md)。环境集中在 [environment.local.json](assets/environment.local.json)，迁移时只改配置。查本机对应版本的帮助、官方示例，再参考已验证代码；本机资料不足才查官方资料并记录版本差异。不猜 feature type、属性键、枚举值或表达式。每个新接口保存“来源位置—用法—版本—验证等级”的证据。目录存在不等于许可可用。
2. **新建**：将需求组织成参数/函数、几何与有意义的选择、材料、物理/初始边界条件、坐标系/配对/耦合的依赖图。按依赖创建 Java API 代码。常量参数和选择判据来自本任务；不复制案例实体号或实验条件。
3. **已有 MPH**：先读 [修改与审计](references/model-audit.md)。只有 MPH 时用 `validate_manifest.py --mph` 散列并返回 `pending_model_inspection`，不声称检查了内部；继续独立准备方案，后续获授权才只读盘点。读取 v2 manifest 时核对哈希、版本、参数/函数、组件、依赖及旧网格/研究/解。未盘点内容用 inventory 状态和 null，只有确认没有才用空数组。默认另存，最小修改。
4. **选择及实际生效设置**：几何结果选择、累计选择、基于位置或语义的选择优先；构建后检查维度、实体数量与空间位置。几何变化后重新检查所有受影响选择、配对两侧、材料覆盖及物理绑定。检查实际激活、本构模式、属性来源、单位/坐标系、特征顺序与覆盖关系，不能只检查节点存在。材料要求按具体物理接口和实际作用域判断。
5. **检查与保存**：生成本任务可执行的 `CheckModel.java`（断言见审计参考）；保存后对重新加载的模型执行检查，并以独立 inspect 阶段核验保存文件，绑定实际输入哈希。已有运行授权时完成保存—卸载—重载，失败不得报通过；退出零、文件存在或完成标记均不足以验收。未授权或不能运行时保留 `not_run/blocked` 及原因。区分几何构建、结构审计、保存重载、网格/求解验证。审查调用接收者和可达调用链：`geom.run()` 允许，`mesh.run()`、`study.run()`、`sol.runAll()` 等不允许；搜索 `.run()` 不能代替审查。
6. **操作审查与影响交接**：执行前独立生成并复核 `operation_review`，绑定输入、操作/范围、未解项处理、目标完整性和运行 pins；ready 只表示准备状态，另核对当前授权。prepare 可交未完成方案，不能称可执行运行包。输入 manifest 不变，输出另建记录；原检查保留原哈希，继承另记依据/范围/限制，不能换哈希冒称重检。旧解 valid 必须有适用模型/来源、节点、参数/时间范围和证据；静态核验不证明解有效。详见 [交接与操作](references/handoff.md)。

## 交付与按需资源

建模交付包含新 `.mph`、可复现 Java 源码与运行入口、简明建模说明/检查日志、`model-manifest.json`。未完成或未运行的部分明确列出，不生成虚假完成包。

- [交接合同](references/handoff.md)、[共同 v2 规范](references/protocol.md)、[公共接口](references/validator-interface.md) 与 [JSON Schema](references/model-manifest.schema.json)：唯一维护源在候选工作区 `handoff-review`，本 skill 携独立副本，不依赖另一 skill 私有脚本。仅消费 `2.0.0`；按发布快照同步，[v1 迁移](references/migration.md) 显式另存并保留原始来源，不补造通过。运行 `scripts/validate_manifest.py`，分别处理 errors、side_errors 和 todos；文件合同通过不等于模型正确、执行就绪或授权。
- [未盘点模板](assets/model-manifest.template.json) 只演示 null/inventory/not_run 的写法，模型路径和零哈希是占位，故意不能通过文件核验；不得作为建模完成的 manifest 交付。真实字段只由本任务事实及证据填写。
- 选择统一 `selection_ref` 的 named/all/inline/global/pending，检查归属、维数、几何与引用存在性。目标量使用共同完整字段和显式待定状态，不从旧案例填单位、坐标系或统计定义。未知事项逐项记录责任方、证据、范围及对 solve/resume/export 的影响。
- [InspectModel.java](assets/InspectModel.java) 与 [盘点 API 说明](references/inventory-api.md)：授权后用于只读盘点与重载；区分读取完成、not_read、读取失败和物理检查 not_run，盘点不替代物理断言。
- [窄范围导热读回规则](references/conduction-readback.md)：遇到二维标准各向同性固体导热时，复用同一检查片段生成 Build/Modify/Check，处理默认 Solid 锁定、精确标量/对角形式及 inactive LayerOpacity；不作为整个案例或其他物理接口的默认模板。
- [小型电热耦合建模](references/joule-slab.md)：需要可解析核验的电流—焦耳热小例时，使用独立案例模板检查实际耦合、两侧厚度、材料来源和选择；模型只交接，不求解，不把案例常数推广为默认。
- [小型瞬态导热建模](references/transient-slab.md)：瞬态问题额外核验密度、热容及实际物理初值的来源、表达式、激活与域覆盖；续算不得重写物理初值。
- [温度反馈电热建模](references/nonlinear-joule.md)：检查温度相关电导率、两向耦合与完整边界，计算侧不得通过改变本构或关闭耦合获取收敛。
- [历史证据索引](references/history-evidence.md)：仅当遇到相关选择、旋转配对、本构覆盖等问题时查阅；不要每次扫描整个历史目录。40 Hz、针材料、误差阈值均属于原案例。
- [修改与审计](references/model-audit.md)：需要读取已有模型、修改几何或设计结构检查时阅读。
